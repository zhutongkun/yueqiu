## 3. 2026 正式规则

### 3.1 场地与卡片

- 第 6 页：场地有月球基地坡台、月球资源库、3 张矿石任务卡片、3 张月球环境识别卡片、障碍和两个矿石采集平台；线上赛自行准备 10 张场景卡片。
- 第 7-9 页：矿石有正方体、长方体、圆柱体三种；三个月球环境识别卡片均固定在指定边界位置，离地 300 mm。任务一点靠近资源库，任务二、三位于场地边界的不同任务位置。

这些位置关系与源码插点相符：任务一点位于目标确认阶段；任务二、三分别伴随两次采矿路线，而不是三个点连续巡航。

### 3.2 正式任务顺序

规则第 9-11 页规定：

1. 语音“开始执行任务”后从基地出发并持续显示导航画面。
2. 到达资源库，识别矿石任务卡片并确认需搬运的形状。
3. 自主穿越随机和固定障碍，前往采集区。
4. 到两个采集平台识别并夹取指定矿石；每次往返只能夹一个，夹取后送回资源库放置。
5. 在任务运行过程中依次识别三个“月球环境识别卡片”。
6. 往返两次后停止采矿，返回月球基地，车身恢复至出发状态。

因此，三个识别点不是完整比赛。第三点识别结束后至少还有第二次采矿路线的后退、返回资源库、第二次放置和原流程收尾，随后才进入返航。

### 3.3 识别播报解释

第 10 页先概述“按照任务点顺序依次识别和语音播报”；第 11 页进一步明确“识别完成后，最后回到月球基地”，并给出固定三句格式。用户本次要求又明确规定三个点现场不播、回到基地停车后集中播报。因此本分支采用无歧义的实现：

- 每个识别点只保存结果，不播放类别、成功或完成语音。
- 回基地并确认停车后，严格按 1、2、3 播放三句。
- 失败点保留位置并播放“第 N 个任务点未识别到有效场景元素”，不借用其他点结果。
- 原规则第 11 页的“任务完成”属于返回基地任务的独立播报要求，不能拼进三条识别结果，也不能触发任务重新启动。最终现场是否保留这条独立 WAV，应以裁判最新口径和实机语音资源为准。

第 15 页说明语音内容、识别顺序或漏播会扣分，进一步要求结果槽位与播报顺序不能混用。第 17 页允许语音启动失败时按键启动；这支持把语音、15 秒自动启动和调试服务统一进入同一个一次性启动门禁。第 18 页给出 8 分钟总时长和故障重启规则；“允许重启”指人为重启，不能解释为节点在完成后自动跑第二遍。

## 4. 2025 实现引导

- 第 21 页：旧标准启动步骤为停止 `start_app_node.service`，运行 `roslaunch competition position_correction_pick.launch`，唤醒后说“开始执行任务”；Orin Nano 资料还提示使用 `bash start.sh`。这确认主 launch 和 APP 服务冲突，但不能证明当前实机路径与版本。
- 第 26-27 页：导航点由 `voice_control_navigation.py` 中 `self.control(x, y, yaw, mode)` 调整；重新标定时可读 `/move_base/goal`。这说明现有导航点属于用户/实车调参资产，不能用旧文档坐标覆盖。
- 第 32 页：坡面动作通过 `/voice_control_navigation/back` 调试，`up_ramp_time` 需要按实车距离校准；训练模型是“非必要”。
- 第 32-33 页：旧 YOLOv5 6.2 流程使用 `.engine + .so`，通过 `/yolov5/start` 和 `/yolov5/calibration` 测试。该模型用于原矿石卡片三分类，不能直接替代 Moon 十分类模型。
- 第 35-37 页：确认 `config.yaml`、导航 launch、`automatic_pick.py`、`ramp.py`、`shape_recognition_down.py`、`yolov5_node.py`、`voice_control_navigation.py` 和 `position_correction_pick.launch` 的职责。

旧引导没有 2026 的三个场景任务，因此只能用于还原原采矿、放置、坡面和启动流程，不能决定三个新插点的完成条件。

## 5. 平台技术手册

- 第 13 页：上位机可能是 Jetson Nano B01 4G/64G，也可能是 Orin Nano 8G/128G。
- 第 15-16 页：平台有 S2L 雷达和 ORBBEC 单目结构光深度相机，RGB 支持 640x480@30fps。
- 第 17-18 页：六通道远场麦克风阵列通过 USB 连接，含离线语音处理相关硬件。
- 第 19-20 页：机械臂另有双目结构光深度相机，支持 RGB/深度数据。
- 第 21-22 页：USB 声卡/扬声器用于离线播报，7 寸屏可持续显示导航画面。
- 第 23、28 页：下位机为 STM32F407；上、下位机串口通信，ROS 上位机向底盘传目标速度。标准版资料为 Ubuntu 18.04/ROS Melodic，高性能版为 Ubuntu 20.04/ROS Noetic。
- 第 197-200 页：典型 ROS 工作空间是 `~/ros_ws`，包含 `build/devel/logs/src`，功能代码按 ROS 包组织。
- 第 201 页：开发前停止 `start_app_node.service`，结束后人工恢复；该服务可能占用硬件。
- 第 202 页：STM32 负责速度闭环、编码器、IMU 和底层电机控制，上位机 ROS 节点通过串口发送目标速度。

手册说明了可能的硬件组合，但没有指出当前这台车究竟是 Nano 还是 Orin；不能据此选择预编译 TensorRT engine。

## 6. 还原后的真实比赛主线

```text
等待语音/一次性 15 秒自动启动
-> 驶离基地
-> 资源库目标确认
-> 场景任务点 1（只保存）
-> 穿越障碍并完成平台 1 夹取
-> 场景任务点 2（只保存）
-> 返回资源库并放置 1
-> 完成平台 2 夹取
-> 场景任务点 3（只保存）
-> 继续原后退动作
-> 返回资源库并放置 2
-> 机械臂/对齐/识别节点安全收尾
-> 完整主体任务完成
-> 返航并通过坡道回基地
-> 确认基地到达并停车
-> 按 1、2、3 集中播报
-> COMPLETED，节点生命周期内不再自动执行
```
